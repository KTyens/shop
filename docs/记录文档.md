### 0.3 结账修复（`29c0e2c`）

**现象**  
点支付提示：`Checkout API returned an empty response`，但 body 里已有  
`https://checkout.stripe.com/c/pay/cs_live_...`（说明 Stripe session **已创建成功**）。

**原因**  
前端 `readJsonResponse` 要求**完整合法 JSON**；实际响应被截断或夹杂杂讯时 `JSON.parse` 失败，误报 empty。

**修复**

| 文件 | 改动 |
|---|---|
| `assets/shop-phase4.js` | 解析增强：纯 JSON → 从混合文本抽对象 → **正则捞出 Stripe URL 仍跳转** |
| `api/create-checkout-session.php` | 清输出缓冲、只输出纯 JSON、校验 URL 后 `exit` |

**部署注意**  
- 前端：`shop-phase4` 随 CF `dist` 已更新  
- **后端 PHP 需确认 Serv00 上的 `create-checkout-session.php` 已覆盖**（CF 不部署 api）

### 0.14 2026-07-17 — 登录验证码邮件发不出（Gmail 收不到）

**现象**  
接口返回 “We sent a 6-digit sign-in code…”，但邮箱/垃圾箱都没有。

**原因**  
原实现仅用 PHP `mail()` + `CRTLU_MAIL_FROM`。Serv00 共享主机上 `mail()` 经常静默失败，且 Gmail 拒收无认证发信。

**修复**
- `crtlu_send_mail()`：优先 Resend API → SMTP → mail()
- 队列记录 sent/failed + last_error
- 发码接口返回 `mail_sent`；前台失败时红字提示
- 后台邮件重试走同一发送通道

**你需要在 Serv00 `config.local.php` 配置其一**
```php
define('CRTLU_MAIL_FROM', 'support@你的域名');
// 推荐 Resend:
define('CRTLU_RESEND_API_KEY', 're_xxx');
// 或 SMTP:
// define('CRTLU_SMTP_HOST', 'smtp.xxx.com');
// define('CRTLU_SMTP_PORT', '587');
// define('CRTLU_SMTP_USER', '...');
// define('CRTLU_SMTP_PASS', '...');
// define('CRTLU_SMTP_SECURE', 'tls');
```
临时救急（勿长期开）：`define('CRTLU_LOGIN_CODE_DEBUG', '1');` 会在接口返回验证码。  
后台「邮件队列」也可查看验证码正文。

### 4.1 目标

### 4.3 `specs` 字段约定

- 类型：`Record<string, string>`
- 详情页渲染：`shop/src/pages/products/[slug].astro`  
  - 会自动加上 Brand / Category / Tier / Configurations / SKU / 价格  
  - catalog 里下列 **meta 键不会重复展示为技术参数**（小写匹配隐藏）：  
    `brand`, `category`, `tier`, `configurations`, `sku`, `starting_price`, `shipping_baseline`, `product`, `model`  
  - 注意：JSON 里的 `Model` / `Product` 若首字母大写，页面仍可能显示；当前写法与 V58 历史格式一致。
- **应保留的 meta 键**（更新技术参数时不要删）：
  - `configurations`
  - `starting_price`
  - `brand`
  - `shipping_baseline`（投影机等有运费基线时）
- 技术参数建议用英文、简洁、面向顾客，键名 Title Case，例如：
  - `Chipset`, `GPU`, `OS`, `Memory`, `Storage`, `Video Output`, `Wi-Fi`, `Ethernet`, `Bluetooth`, `USB`, `Other Ports`, `Power`, `Dimensions`, `Accessories`
  - 投影机额外：`Native Resolution`, `Brightness`, `Contrast Ratio`, `Projection Size`, `Keystone` 等

## 5. 详情页如何显示 specs

文件：`shop/src/pages/products/[slug].astro`

构建时把 `series` 序列进页面；客户端 `renderProduct()` 合并 `baseSpecs` + `product.specs` 填入 `#specGrid`。

因此：

- **只改 `data/catalog.json` 不够上线**，必须 `npm run build` 再提交/部署 `dist/products/*/index.html`（或至少保证 CF 用 build 命令从源码构建）。
- 当前仓库实践：提交 `data/` + `public/data/` + 重建后的 `dist/` 一并推送。

# 1. 改 catalog

python3 - <<'PY'
import json
from pathlib import Path
d=json.loads(Path("data/catalog.json").read_text())
pub=[s for s in d["series"] if s.get("status")=="published"]
meta={"configurations","starting_price","brand","shipping_baseline"}
print("series", len(pub))
print("variants", sum(len(s.get("variants") or []) for s in pub))
missing_img=[]
for s in pub:
    for img in [s.get("image"), *(s.get("gallery") or [])]:
        if not img: continue
        if not (Path("public")/img).exists() and not Path(img).exists() and not (Path("assets")/Path(img).name).exists():
            # 常见路径：assets/products/... 相对 shop 根或 public
            p1=Path(img); p2=Path("public")/img; p3=Path("assets")/img.replace("assets/","",1) if img.startswith("assets/") else None
            ok=p1.exists() or p2.exists() or (Path(img).exists())
            # 简化：检查 public 下
            if not (Path("public")/img).exists() and not Path(img).exists():
                # images live under public/assets or assets copied at build
                from pathlib import Path as P
                candidates=[P("public")/img, P(img), P("assets")/img[len("assets/"):] if img.startswith("assets/") else P("x")]
                if not any(c.exists() for c in candidates if str(c)!="x"):
                    missing_img.append((s["id"], img))
no_tech=[s["id"] for s in pub if not [k for k in (s.get("specs") or {}) if k not in meta]]
print("missing images sample", len(missing_img), missing_img[:3])
print("no tech specs", no_tech)
PY
